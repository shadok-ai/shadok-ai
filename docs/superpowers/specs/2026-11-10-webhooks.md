# Webhooks — wake an agent from outside, like a cron

## Goal

Let an outside system (CI, a form, a monitoring tool, Zapier…) prompt an agent
with an HTTP call, the event-driven twin of a scheduled prompt. Secure, but
simple for a first version.

## Shape

- A webhook = `{ id, sessionId, name, prompt, tokenHash, enabled }`, stored per
  launch directory at `~/.shadok-ai/webhooks/<enc>.json` (600).
- Call: `POST /hooks/<id>` with `Authorization: Bearer whk_…` (or
  `X-Shadok-Webhook-Token`, or `?token=` for URL-only senders). Answers `202`
  and drives the agent in the background with
  `⚡ [webhook] "<name>" was called.\n\n<prompt>\n\n<fenced untrusted payload>`.
- Management (browser person only): create / edit name·prompt·enabled /
  rotate token / delete, from the agent's ⏰ Schedule popin.

## Security choices

| Risk | Answer |
|---|---|
| Token stolen from disk | Only SHA-256 stored; the token is shown once. |
| Guessing ids / tokens | 256-bit token, constant-time compare, one `404` for unknown id, disabled hook and wrong token. |
| An agent opening a door into itself (prompt injection) | Every write is `requestFromBrowser` — a person's cookie, no agent key. |
| Payload telling the agent what to do | Payload after the owner's prompt, fenced, labelled untrusted, ``` neutralised, 16 kB cap. |
| Flooding | Per-hook queue capped at 10 → `429`; one turn at a time per hook. |
| Cross-group | List and writes go through `mayActFor`; a hook cannot be repointed at another agent. |

## Deliberately left out (v1)

- HMAC signature verification (GitHub `X-Hub-Signature-256`, Stripe…): the
  bearer token covers "simple"; HMAC is the natural v2 for senders that sign.
- Persistent queue: a call queued when the server restarts is lost.
- Per-hook rate limit beyond the queue cap; IP allowlists.
- Agent-side skill to create webhooks (refused on purpose, see above).
- Returning the agent's answer to the caller (fire-and-forget only).
